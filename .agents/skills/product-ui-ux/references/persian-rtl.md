# فارسی، RTL و دسترس‌پذیری

این چک‌لیست راهنمای اجراست؛ عبور از آن به‌تنهایی تأیید انطباق WCAG نیست. جهت و زبان واقعی هر محصول مقدم‌اند.

## زبان و چیدمان

- در صفحه فارسی `lang="fa"` و `dir="rtl"` را در ریشه تعیین کن؛ `direction` در CSS جای اعلام زبان را نمی‌گیرد.
- از `margin-inline`، `padding-inline`، `inset-inline-start` و `text-align: start` استفاده کن. با برعکس‌کردن آرایه داده یا `row-reverse`، ترتیب منطقی DOM و Tab را خراب نکن.
- ایمیل، URL، کد، شناسه و شماره تلفن اغلب بخش LTR می‌خواهند؛ جهت را روی همان بخش تعیین کن. برای محتوای ناشناخته کاربر `bdi` یا `dir="auto"` را با رشته‌های واقعی آزمایش کن.
- فلش عقب/جلو را براساس معنای ناوبری تطبیق بده. لوگو، آیکون پخش، عکس و نمودار را کورکورانه آینه نکن. جهت محور زمان/مقدار نمودار نیاز به تصمیم روشن دارد.
- موارد تست: «پرداخت invoice-42 انجام نشد»، `ali@example.com`، `+98 912 000 0000`، `۱۲۳٬۴۵۶ تومان`، منفی و درصد، URL بلند، نام طولانی و متن بدون فاصله.
- ی/ک فارسی، نیم‌فاصله، اعداد فارسی و لاتین و کپی‌پیست را بررسی کن. ورودی شماره را بدون توضیح رد نکن؛ نمایش محلی را از قالب ذخیره و ارسال به API جدا نگه دار.
- ریال و تومان را صریح بنویس و تبدیل را بدون قرارداد محصول حدس نزن. تقویم جلالی/میلادی، منطقه زمانی و زمان ذخیره/نمایش هم باید مشخص باشند؛ هر محصول فارسی الزاماً تهران یا جلالی نیست.

```html
<html lang="fa" dir="rtl">
  <!-- داخل بدنه: -->
  <label for="email">ایمیل</label>
  <input id="email" type="email" dir="ltr" autocomplete="email">
  <p>مسئول پروژه: <bdi>Alex نادری</bdi></p>
</html>
```

## تایپوگرافی و محتوا

- فونت موجود محصول را حفظ کن. پیش از افزودن فونت فارسی، مجوز، وزن‌ها، ارقام، جایگزین محلی و هزینه دانلود را بررسی کن؛ کاشی مجوز استفاده از هر فونت دلخواه نیست.
- بدنه حدود ۱۶ CSS px و line-height حدود ۱٫۶ تا ۱٫۹ می‌تواند نقطه شروع باشد؛ کیفیت واقعی را با فونت، نمایشگر و طول متن محصول بررسی کن، نه با یک عدد ثابت.
- ارتفاع کنترل‌ها نباید حروف و اعراب فارسی را قطع کند. روی متن فارسی letter-spacing لاتین تحمیل نکن.
- متن دکمه نتیجه عمل را بگوید: «ساخت پروژه» روشن‌تر از «ادامه» است، مگر جایی که واقعاً ادامه مرحله باشد.
- خطای مناسب: «شماره موبایل باید ۱۱ رقم و با ۰۹ شروع شود» فقط اگر همین قاعده معتبر محصول است. متن عمومی «ورودی نامعتبر است» کمک کمی به بازیابی می‌کند.

## چک‌های دسترس‌پذیری

- HTML معنایی، landmarkها و headingهای منطقی؛ کنترل واقعی برای عمل و لینک واقعی برای ناوبری.
- نام قابل دسترس، label دائمی، hint مرتبط با `aria-describedby`، خطای مرتبط و مشخص‌کردن فیلد نامعتبر. نام کنترل باید با نوشته قابل مشاهده سازگار باشد.
- تمام مسیر با کیبورد قابل انجام باشد؛ focus دیده شود و پشت نوار چسبان پنهان نماند. modal باید focus را مدیریت کند، راه خروج مناسب بدهد و پس از بستن آن focus بازگردد.
- پیام وضعیت با روش مناسب مانند live region اعلام شود؛ تغییرهای مکرر و بی‌دلیل screen reader را اشباع نکند.
- رنگ تنها نشانه خطا/موفقیت نباشد. کنتراست متن عادی حداقل ۴٫۵:۱؛ متن بزرگ حداقل ۳:۱ با تعریف WCAG: ۱۸pt عادی یا ۱۴pt bold، تقریباً ۲۴px یا ۱۸٫۶۷px در CSS. لوگو، متن تزئینی و برخی موارد استثنا دارند؛ مورد را مستند کن.
- برای اجزای بصری لازم کنترل‌ها و گرافیک اطلاعاتی، معیار non-text contrast معمولاً ۳:۱ با رنگ مجاور است؛ معیار و استثنا را جدا بررسی کن.
- هدف اشاره‌گر در WCAG 2.2 AA معمولاً حداقل ۲۴×۲۴ CSS px یا مشمول یکی از استثناهاست: فاصله، کنترل معادل، متن درون‌خطی، کنترل عامل کاربر یا ضرورت. هدف ۴۴×۴۴ توصیه مناسب لمس است؛ آن را الزام عمومی AA معرفی نکن.
- reflow را در عرض معادل ۳۲۰ CSS px و بزرگ‌نمایی متن ۲۰۰٪ بررسی کن؛ جدول/نمودار ممکن است استثنای دوبعدی داشته باشد. تصویربرداری ۳۶۰px این آزمون را پوشش نمی‌دهد.
- حرکت غیرضروری را برای `prefers-reduced-motion` کم کن؛ اطلاعات و نتیجه عمل همچنان قابل فهم بمانند. autoplay و flashing بررسی جدا می‌خواهند.
- از تست با کیبورد، screen reader و کاربران دارای نیاز دسترس‌پذیری غافل نشو. ابزار خودکار فقط بخشی از مشکلات را پیدا می‌کند.

## وضعیت‌ها و موبایل

| وضعیت | سؤال پذیرش |
| --- | --- |
| Loading | وضعیت روشن است؟ ارسال تکراری مهار می‌شود؟ |
| Empty | فرق «داده نداریم» و «نتیجه فیلتر نداریم» روشن است؟ |
| Error | راه بازیابی هست و داده واردشده حفظ می‌شود؟ |
| Success | نتیجه عمل و قدم بعد مشخص است؟ |
| Permission | دلیل محدودیت و راه مجاز ادامه مشخص است؟ |
| Offline | وضعیت داده و امکان تلاش دوباره روشن است؟ |
| Long content | متن/جدول بدون پوشاندن کنترل‌ها قابل استفاده است؟ |

کیبورد نرم‌افزاری، input mode، safe area، دکمه چسبان، zoom و جدول موبایل را با محصول واقعی آزمایش کن. روی hover به‌عنوان تنها راه دسترسی حساب نکن.

منابع رسمی معیارهای کنتراست و اندازه هدف از مخزن W3C بررسی شده‌اند؛ لینک‌ها و محدودیت دسترسی در [گزارش تحقیق](research.md) آمده‌اند. سایر موارد این فایل راهنمای مهندسی‌اند و ادعای پژوهش میدانی جدید نیستند.
